What this is

Lovable can sync your project to GitHub (Settings → Git → Connect GitHub), which creates a fresh repo with your full source. Emergent imports from GitHub, but only through its UI — there is no import API or deep link. The migrator bridges that gap: it inventories the Lovable-synced repo and generates a migration pack — a repo report, a paste-ready EMERGENT.md prompt for Emergent's agent, a .env.example, and an acceptance checklist — so the import takes minutes instead of an afternoon of archaeology.

Four ways to use it

1. Web analyzer

Open the migrator, paste a public repo URL, hit Analyze repo. For private repos, add a GitHub token (sent only to api.github.com, never stored) or use the CLI instead. Everything runs in your browser.

2. CLI script

migrate-to-emergent.sh clones the repo locally and produces the same EMERGENT.md pack — best for private repos and full local runs:

./migrate-to-emergent.sh --repo https://github.com/you/your-lovable-app
# options: --branch emergent-import  --push  --workdir PATH

It inventories dependencies, supabase/ migrations and functions, env var names, scans for secrets and tracked .env files, drops .lovable/ builder artifacts, and commits an emergent-import branch.

3. MCP server

For Claude Code, Codex, and other MCP clients. Tools: analyze_repo and generate_migration_pack over stdio. Add to .mcp.json, run npm install @modelcontextprotocol/sdk, pass github_token per call for private repos.

4. Agent skill

Installs the whole playbook into your agent:

npx skills add mike-demo/lovable-emergent-migrator

All four ship open source at github.com/Mike-Demo/lovable-emergent-migrator (MIT).

Importing into Emergent, step by step

  1. Sync Lovable to GitHub. In Lovable: Settings → Git → Connect GitHub. Confirm the repo is up to date.
  2. Generate the pack. Run the analyzer above (or the CLI) and review the report — especially any secret or tracked-.env warnings.
  3. Connect GitHub in Emergent. Profile icon → Connect GitHub → authorize and grant access to the repo.
  4. Pull the repo. New task → the GitHub button in chat → Pull from GitHub → pick the repo and branch.
  5. Paste the prompt. The generated EMERGENT.md goes in as your first message to Emergent's agent. It instructs the agent to adapt your codebase, not rebuild it, and wires the backend per the decision below.
  6. Hand over secrets properly. Supabase URL/keys go into Emergent's secret store — never pasted as committed code.
  7. Work the checklist. Build, auth flow, data flow, edge functions, then cut over. Keep the Lovable project alive until Emergent is confirmed as the source of truth.

The backend decision

Emergent's native stack is FastAPI + MongoDB. Lovable apps are Vite + React + Supabase. The default migration path keeps Supabase as the backend — your schema, RLS policies, and edge functions already exist, and porting to a different database is the highest-risk part of any migration. The generated prompt encodes this decision and tells Emergent's agent exactly how to re-wire it. If your app has no supabase/ directory, the prompt instead has the agent identify the real backend and ask you for its URL and keys before inventing anything.

What travels, what doesn't

  • Travels: all React source, package.json, supabase/migrations/ (schema + RLS), supabase/functions/ (edge functions), public assets, full git history.
  • Stays behind: database rows (exports contain zero data), Storage bucket files, secrets (re-enter in Emergent), Lovable hosting, preview URLs, and analytics.

Privacy

The web analyzer runs entirely client-side; the only network calls are to api.github.com. Tokens are kept in page memory and never stored. The CLI and MCP server run on your own machine.
